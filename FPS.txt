코루틴 (Coroutine)
- 유니티에서 제공하는 기능 중 하나.
- 코드의 함수 내에서 어떤 구문을 처리하는 도중에 그 처리를 대기시키고 다른 처리로 넘어가게 하거나, 여러가지 함수를 동시에 병렬로 처리되게 하는 기능 - 비동기 처리 
- 함수에 진입했을 시 그 함수의 끝까지 처리를 하지 않고 중간에 함수 밖으로 나가게 해주는 기능 
- 그리고 함수로 다시 돌아왔을 때 나가기 전에 처리했던 다음 부분 부터 이어서 실행을 하게 해준다.

virtual - override -> 상속 시 같은 이름의 함수를 다른 기능으로 쓰기 위해서 사용
-> override 상속 받은 함수, virtual 상속하는 함수

게임 루프 (Game Loop)
 - 게임이 실행되는 동안 데이터 초기화부터 유저 입력 처리, 게임 세계 업데이트, 화면에 그려주기
 -> 게임 종료 시 까지 계속 반복

		데이터 초기화
		          ㅣ
		입력 받기
		게임 세계 정보 업데이트
		화면에 렌더링
		          ㅣ
		게임 종료
입력 받기 : Input 클래스를 이용해서 키보드 입력, 마우스 클릭, 마우스 커서의 좌표, 터치 위치, 터치를 한 상태인지, 손가락을 뗀 상태인지 등등의 상태를 가져온다.

게임 세계 정보 업데이트 : 클래스의 Update 함수에서 매 프레임 마다 처리할 코드를 넣는다.
			예) 캐릭터의 위치를 매 프레임마다 이동
			      시간의 변화
			      시간이 흐를 때 마다 반복적으로 처리 되어야 하는 것들을 처리
			      Update, FixedUpdata, LateUpdate
Update : 매 프레임 마다 호출, 일반적인 업데이트 처리 시 사용
FixedUpdate : 고정된 주기마다 호출. 물리 처리를 반복적으로 할 때 사용
LateUpdate : Update가 호출 된 이후 호출되는 함수. 카메라 등의 Update 직후에 처리해야 할 것이 있을 때

조명(Lighting)
 - 게임 씬의 전체적인 분위기, 공간감, 실사느낌 조성에 큰 기여
 - 조명을 잘 이용하면 저수준의 모델도 일정 수준의 코퀄리티로 보이게 할 수 있다
 - 사실적인 느낌의 그림자와 명암을 만들어주기 때문

유니티에서 제공하는 조명 시스템의 종류
 - 실시간 조명 (Realtime Lighting) : 실시간으로 계산되는 조명. 부하가 아주 크다.
			         그림자의 방향도 실시간으로 바뀐다.
 - 미리 만들어진 조명 (Baked Light) : 맵상에 배치된 조명과 오브젝트들을 이용해서 미리 텍스처로 만들어 둔다. -> 라이트맵
			             실시간으로 계산하지 않기 때문에 부하가 적다.
			             그림자의 방향 변경 등을 실시간으로 바꾸지 못한다.
 - 혼합 조명 (Mixed Lighting) : 맵상에 고정되어 있는 오브젝트의 경우 미리 만들어진 조명을 적용
			 움직이는 오브젝트의 경우에는 실시간 조명을 적용

조명의 종류
 - Directional Light (방향광) : 멀리서부터 한쪽 방향으로 내리쬐는 조명
			맵의 전체에 영향을 주는 조명
 - Point Light (점광원) : 특정 지점에서 사방으로 퍼지는 빛.  예) 전구, 게임에서는 특정 캐릭터의 위치에 방어막 효과 같은 것을 만들 때
						       던전에서 램프를 켰을 때의 효과
 - Spot Light (스포트라이트) : 손전등, 연극 무대에서 특정 배우만 비추는 조명

유니티 상에서 언제 무엇이 실행되는가?
유니티에서 기본으로 제공하는 함수들 : 상황에 따라 자동 호출

Awake : 오브젝트가 생성되면 가장 먼저 자동으로 호출되는 함수. 처음에 1번만 호출. 다른 컴포넌트를 찾아서 초기화 하는 시점에 적합한 함수
OnEnable : 오브젝트가 활성화될 때마다 호출되는 함수. 이벤트 등록을 할 때 적합한 함수
Start : 첫 프레임이 시작되기 직전에 1회 호출. 데이터 초기화를 할 때 적합한 함수
Update : 매 프레임 호출. 대부분의 게임 로직이 처리되는 함수 (사용자의 입력, 게임의 전체적인 상태를 갱신 : 게임 플레이, UI)
OnDisable : 오브젝트가 비활성화 될 때마다 호출. 이벤트 해지를 할 때 적합한 함수
OnDestroy : 오브젝트가 파괴될 때 호출. 리소스 정리를 할 때 적합한 함수
OnCollisionEnter : 오브젝트에 추가된 Collider에 충돌이 감지되었을 때 호출
OnTriggerEnter : 오브젝트가 트리거에 충돌했을 때 호출

8.20
NavMesh (Navigation Mesh)
길찾기 데이터를 3D 메시 형태로 생성해서 플레이어나 적 캐릭터가 이동할 수 있는 경로 데이털르 생성하는 길찾기 알고리즘.

길찾기(PathFinding)의 핵심 아이디어
 - 게임에서 길찾기는 갈 수 있는 곳을 이해한느 것
 - NavMesh는 갈 수 있는 곳을 폴리곤(Mesh) 형태로 미리 만들어 둔 데이터
장점
 - 타일 기반보다 부드러운 경로 생성이 가능
 - 경계/경사/계단 등에 대한 대응이 좀 더 용이하다.

유니티 NavMesh의 구성요소
NavMesh 데이터 : Bake를 해서 생성한 이동 가능 표면의 데이터
NavMeshAgent 컴포넌트 : 오브젝트에 붙여서 NavMesh 위에서 이동, 회피
NavMeshObstable : 동적 장애물

Bake
씬에 배치되어 있는 '고정' 지형이나 오브젝트를 탐색을 해서 이동 가능 표면을 계산해서 저장하는 과정
바닥/경사/계단 등의 기하정보를 에이전트의 높이/반지름/최대 경사 기준으로 필터링 해서 NavMesh 생성
 - Bake 시 반드시 체크되어야 할 사항
  바닥/벽/오브젝트에 Collider가 있어야 하고 static 속성이 체크 되어야 함

경로 탐색 흐름
에이전트가 목적지 위치를 받음
NavMesh 상에서 가장 가까운 점으로 보정
경로 계산(코너/직선 구간)
이동/회전을 하면서 장애물 회피
주기적으로 목적지 갱신

NavMeshAgent의 주요속성
Speed : 최고 속도
Acceleration : 가속도
Angular Speed : 회전 속도
Stopping Distance : 목적지에 가까워졌을 때 멈추는 거리
Auto Braking : 목적지 근처에서 자동 감속 여부
Obstable Avoidance :  회피 품질 (고품질일수록 비용이 올라감)
Base Offset : 바닥에서의 높이

SetDestination(Vector3 pos) : 목적지 지정(경로를 계산)

8.21

적의 근접 공격
 - 플레이어에게 다가간다 -> 한 번 때린다 -> 잠깐 쉰다 -> 또 때린다

1. 추적 : 적은 NavMeshAgent 기반으로 플레이어 좌표를 향해 게속 추격을 한다.
2. 도착 판단 : 플레이어와의 거리를 재서 지정된 공격 가능 거리에 도달하면 도착으로 간주
3. 멈추기, 바라보기 : 플레이어와 적이 너무 가까이 달라붙지 않게 NavMeshAgent의 속성 중 Stopping Distance 근처에서 멈추고,
		  몸을 천천히 플레이어 쪽으로 회전
4. 한 번 때리기 : 공격 범위라는 작은 원을 내 앞쪽에 만들어서 그 원 반경 안에 플레이어가 들어가 있으면 플레이어의 체력을 깎는다.
5. 쿨타임 : 바로 또 때리지 않게 일정 시간 기다리게 한다.
6. 다시 추적 : 플레이어가 멀어지면 다시 쫓아가고 가까워지면 공격

핵심 기법
거리에 기반을 둔 상태 전환 : 멀면 -> 쫓아간다. 가까우면 -> 공격한다. if(거리가 가까우면) else
원 형태의 범위 판정 : Physics.OverlapSphere 함수로 원 안에 플레이어가 들어왔는지 체크
쿨타임 : Time.time을 이용해서 지금이 공격 가능한 시간인지 비교
